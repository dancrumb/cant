# 0042. The `cant::IO` module

- **Status:** Accepted
- **Date:** 2026-11-22

## Context

Several ADRs leave reading and writing to `cant::IO`:

- [ADR 0040](0040-standard-streams.md) gives a program the process's standard streams, `@stdin`, `@stdout` and `@stderr`, of two unnamed built-in types: the input stream type and the output stream type. It leaves to `cant::IO` which actions read and write them, their parameters, whether `write`'s stream is optional, how text is encoded, what happens when a stream is closed or fails, and whether concurrent writes are kept whole.
- [ADR 0015](0015-files.md) leaves reading a `FILE`'s contents, and writing a new file, to `cant::IO`. A `FILE`'s stream facet reads its contents ([ADR 0017](0017-faceted-types.md)), and Cant code can only reach it through a native action ([ADR 0029](0029-accessing-facets.md)).
- Earlier examples call `IO::write("Hello World!")`, with no stream ([ADR 0012](0012-base-types.md), [ADR 0038](0038-namespaces-from-imports.md)).

`cant::IO` is a standard library module, so it is a native module that ships with the interpreter ([ADR 0031](0031-module-resolution.md), [ADR 0036](0036-native-modules.md)). Its declarations are written in Cant, with `native` lines, and may use internal types that a program can't write.

## Decision

### The module

`cant::IO` is declared by this Cant module, its bridge to the TypeScript that implements it:

```cant
export error StreamError
    data
        reason: TEXT

export action write(message: TEXT, stream?: WriteStream := @stdout): VOID raises StreamError
    native "./IO.js"

export action read(stream?: ReadStream := @stdin): [NUMBER] raises StreamError
    native "./IO.js"

export action readline(stream?: ReadStream := @stdin): TEXT? raises StreamError
    native "./IO.js"
```

- **Where it lives.** The module is part of the compiler, as `stdlib/IO.cant` in `@dancrumb/cant-compiler`, which loads it when a program imports `cant::IO`. So the compiler, the language server and `cant check` check calls against these declarations, and a hover shows them.
- **Its implementation.** The interpreter provides the implementation of every standard library action itself ([ADR 0031](0031-module-resolution.md)), so a compiled program records `write`, `read` and `readline` as standard actions, and the module named by `native` isn't looked for next to the declarations.

### Stream types

`WriteStream` and `ReadStream` are `cant::IO`'s names for the stream types of [ADR 0040](0040-standard-streams.md):

| Type | Values |
| --- | --- |
| `WriteStream` | The output stream type: `@stdout` and `@stderr` |
| `ReadStream` | The input stream type, `@stdin`, and any `FILE` |

- **Internal.** They are internal types, like `Collection<T>` ([ADR 0021](0021-collections.md)). The compiler defines them, and they are in scope only in standard library modules, which is how `IO.cant` is valid. `cant::IO` doesn't export them, so in a program, `ReadStream` and `IO::ReadStream` are names that don't exist, and a program still can't name a stream type ([ADR 0040](0040-standard-streams.md)).
- **`FILE` is a `ReadStream`.** A `FILE` can be passed where a `ReadStream` is expected, and is read through its stream facet ([ADR 0017](0017-faceted-types.md)). This is the one place a `FILE` can be used where something other than a `FILE` is expected, and it doesn't make a `FILE` a stream anywhere else: it still can't be compared with `@stdin`, for example.
- **A `FILE` is not a `WriteStream`.** A `FILE`'s stream facet only reads, and a `FILE` is identified by its URL, which can be a `data:` URL that holds its contents ([ADR 0017](0017-faceted-types.md)), so writing to one would change what it is. Writing to the output streams is a compile-time error for a `FILE` and for `@stdin`, as giving any value of the wrong type is.

### `write`

`write` writes `message` to `stream`, encoded as UTF-8, with nothing added: no line break, unless `message` ends with one.

- **The stream is optional.** Left out, it is `@stdout`, so `IO::write("Hello World!")` writes to standard output. That call gives `write`'s one required parameter without naming it ([ADR 0020](0020-action-parameters.md)). A call that also gives the stream names both, as in `IO::write(message := "Failed", stream := @stderr)`.
- **When it returns.** `write` returns once the stream has accepted the whole message, which may be before the operating system has passed it on.
- **Whole messages.** Each call's message is written whole, and messages are written in the order the calls are made, even when several triggers' actions write to the same stream while others wait on native calls ([ADR 0036](0036-native-modules.md)).

### `read`

`read` reads everything left in `stream`, waiting until the stream ends, and returns its bytes, in order, each a `NUMBER` from 0 to 255.

- **The stream is optional.** Left out, it is `@stdin`, so `IO::read()` reads standard input. Since `read` then has no required parameter, a stream given to it is named, as in `IO::read(stream := upload)` ([ADR 0020](0020-action-parameters.md)).

- **Standard input.** Reading `@stdin` waits until standard input ends, such as when a pipe closes or the user types the end-of-input key. Once it has ended, reading it again gives `[]`.
- **Files.** Reading a `FILE` reads its contents from the start, each time it is read, through a fresh stream facet.
- **No decoding.** `read` doesn't turn bytes into `TEXT`. An action that decodes bytes is left for later (see [Deferred](#deferred)).

### `readline`

`readline` reads the next line of `stream` and returns it as `TEXT`, decoded as UTF-8, without its line break. It is for interactive input, such as answers typed at a prompt, which `read` can't give until standard input ends.

- **The stream is optional.** Left out, it is `@stdin`, so `IO::readline()` reads the next line typed, and returns as soon as it ends.
- **Line breaks.** A line ends at a line feed, `\n`. A carriage return just before it, as in `\r\n`, is part of the line break, so it isn't in the line either. An empty line is `""`.
- **The end of the stream.** When the stream ends after some text with no line break, that text is the last line. Once the stream has ended with nothing left, `readline` returns `NOTHING`, so the return type is `TEXT?` and a program checks it with `isEmpty` ([ADR 0016](0016-handling-optional-values.md)).
- **Only the line is taken.** `readline` takes the line and its line break from the stream, and no more, so a later `readline` or `read` reads what follows it.
- **In order.** Calls that read the same stream at the same time, such as from several triggers' actions, each get a whole line, in the order the calls are made.
- **Decoding.** Bytes that aren't valid UTF-8 are each decoded as U+FFFD, the replacement character.
- **Files.** A `FILE` is read from the start each time, as by `read`, so `readline` gives its first line, or `NOTHING` for an empty file.

```cant
IO::write("Your name? ")
name := IO::readline()
if name instanceOf IO::StreamError
    return
if isEmpty name
    IO::write("Nobody there.\n")
else
    IO::write("Hello, ${name}!\n")
```

### `StreamError`

`write`, `read` and `readline` raise `StreamError` when the stream fails, and never panic for it:

- writing to a stream that is closed or broken, such as `@stdout` piped to a program that has exited;
- reading a stream that fails part way;
- reading a `FILE` whose stream facet can't be derived, such as one whose URL no longer points to anything ([ADR 0036](0036-native-modules.md)), or that the operating system doesn't let the interpreter read.

Its `reason` says what went wrong, in words for people, such as the operating system's message. A program shouldn't depend on its exact text.

A program handles a `StreamError` like any other error ([ADR 0023](0023-error-handling.md)). For example, a program that writes a log line can choose to `ignore` the result, so that a closed log doesn't stop it.

### Native code

The interpreter gives `IO.js` each stream as [ADR 0040](0040-standard-streams.md) says, as `process.stdin`, `process.stdout` or `process.stderr`, and each `FILE` as a `CantFile` ([ADR 0036](0036-native-modules.md)). `IO.js` is part of the interpreter, so it can recognise those values, which no other native module receives.

## Deferred

- **Decoding and encoding.** Actions that turn bytes into `TEXT`, and `TEXT` into bytes, in UTF-8 or other encodings.
- **Reading in pieces.** Actions that read a stream a chunk of bytes at a time, for input too large to hold at once, and reading a `FILE` a line at a time, past its first line.
- **Writing bytes.** Writing a `[NUMBER]` of bytes to a stream.
- **Writing files.** Creating a new `FILE` from bytes or text ([ADR 0015](0015-files.md)).
- **Other streams.** Streams that a program opens itself, such as to a network connection.
- **Naming the stream types.** Exporting `ReadStream` and `WriteStream`, so that a program can write actions that take a stream, such as a logger whose caller chooses where it writes ([ADR 0040](0040-standard-streams.md)).
- **Test cases.** Giving a `TestCase`'s action streams of its own, to check what it writes ([ADR 0037](0037-test-case-trigger-source.md), [ADR 0040](0040-standard-streams.md)).

## Consequences

- A program can write text to standard output and standard error, and read standard input and files, with one module and three actions.
- `IO::write("Hello World!")` is valid, so the earlier examples work as written, and a program names a stream only when it writes somewhere else.
- Every write and read can raise `StreamError`, so a program handles the result of each call, by checking, passing, ignoring or using it ([ADR 0023](0023-error-handling.md)). Calling `write` as a statement, as in `IO::write("Hello World!")`, doesn't use its result, which ignores it, so a program that only writes to its terminal needs nothing more. A closed pipe never panics a program.
- `read` returns bytes, so a program can read any file, but can't yet do much with text it reads until decoding actions exist. `read` holds the whole stream in memory, so it isn't suited to very large inputs or to interactive programs, which use `readline`.
- `readline` gives `TEXT`, so an interactive program can read and use answers as they are typed. Its result can hold `NOTHING` as well as an error, so a program checks for both.
- A `FILE` can be read but not written, so files stay as [ADR 0015](0015-files.md) and [ADR 0017](0017-faceted-types.md) describe them.
- `ReadStream` and `WriteStream` aren't exported, so a program still can't write an action that takes a stream. Exporting them later won't break any program.
- `IO.cant` uses the internal types, so it is valid only as a standard library module. The compiler and the language server check the files in `@dancrumb/cant-compiler`'s `stdlib` folder as the standard library modules they declare, so editing `IO.cant` shows no errors for them. A copy of it anywhere else is an ordinary module, which can't write them.
- Both streams have defaults, so `read`'s stream, unlike `write`'s message, always has to be named when it is given.
