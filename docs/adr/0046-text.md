# 0046. The `cant::Text` module

- **Status:** Accepted
- **Date:** 2026-11-22

## Context

A program can build `TEXT` with interpolation ([ADR 0008](0008-strings.md)) and compare it ([ADR 0019](0019-operators.md)), but it can't take text apart: count its characters, find a part of it, split it into words, or remove the spaces around it. Text that a program reads, such as a line typed at a prompt ([ADR 0042](0042-io.md)), often needs all of these before it can be used, for example before `cant::Conversion` reads it as a number ([ADR 0045](0045-conversion.md)).

Each of these needs to say what a character is. No ADR says so yet:

- [ADR 0008](0008-strings.md)'s `\u{…}` escape writes one Unicode code point.
- [ADR 0019](0019-operators.md) orders text by UTF-16 code unit, as JavaScript does, which splits a code point above `FFFF`, such as most emoji, into two.
- What people see as one character, a grapheme cluster, can be several code points, such as a letter and an accent, or a family emoji. Which code points form one depends on the version of Unicode's rules the runtime has.

`cant::Text` is a standard library module, so it is a native module that ships with the interpreter ([ADR 0031](0031-module-resolution.md), [ADR 0036](0036-native-modules.md)).

## Decision

### The module

`cant::Text` is declared by this Cant module, its bridge to the TypeScript that implements it:

```cant
export action length(text: TEXT): NUMBER
    native "./Text.js"

export action split(text: TEXT, delim?: TEXT := " "): [TEXT]
    native "./Text.js"

export action trimLeft(text: TEXT): TEXT
    native "./Text.js"

export action trimRight(text: TEXT): TEXT
    native "./Text.js"

export action trim(text: TEXT): TEXT
    native "./Text.js"

export action slice(text: TEXT, start?: NUMBER := 0, end?: NUMBER): TEXT
    native "./Text.js"

export action charAt(text: TEXT, index: NUMBER): TEXT?
    native "./Text.js"

export action repeat(text: TEXT, times: NUMBER): TEXT
    native "./Text.js"
```

Like `cant::IO`, it lives in the compiler, as `stdlib/Text.cant` in `@dancrumb/cant-compiler`, and the interpreter provides its implementation ([ADR 0042](0042-io.md)).

### Characters

A character is a Unicode code point. So `"😀"` is one character, though JavaScript counts it as two, and `"é"` written as `e` followed by a combining accent is two, though it looks like one.

Code points are what a `\u{…}` escape writes, and they don't depend on the version of Unicode the runtime has, so every interpreter gives the same answers for the same text. Grapheme clusters are left for later (see [Deferred](#deferred)).

This is only how `cant::Text` counts and indexes. It doesn't change how text is ordered, which is still by UTF-16 code unit ([ADR 0019](0019-operators.md)).

### Indexes

`slice` and `charAt` take positions in the text, which work as an array's indexes do ([ADR 0021](0021-collections.md)):

- they start at 0, so the first character is at 0;
- a negative position counts from the end, so -1 is the last character;
- a fractional position is truncated towards zero, so 1.7 is 1 and -1.7 is -1.

None of the actions raise errors. A position past either end is not an error, as reading past the end of an array isn't:

- `charAt` gives `NOTHING`, so its result is `TEXT?`, like `a[i]` on an array.
- `slice` takes a position past either end as that end. `end` is the end of the text when it is left out, and an `end` at or before `start` gives `""`.

### The actions

- **`length(text)`** is the number of characters in `text`.
- **`split(text, delim)`** is the pieces of `text` between each `delim`, in order. Where two `delim`s are next to each other, or one is at an end, there is an empty piece, so `Text::split("a  b")` is `["a", "", "b"]`, and text with no `delim` is one piece. `delim` is `" "` when it is left out. When `delim` is `""`, each character is a piece, so `""` has none.
- **`trimLeft(text)`, `trimRight(text)` and `trim(text)`** remove white space from the start of `text`, its end, or both. White space is what Unicode calls white space, such as spaces, tabs and no-break spaces, and line breaks, as JavaScript's `trim` removes them.
- **`slice(text, start, end)`** is the characters from `start` up to, but not including, `end`.
- **`charAt(text, index)`** is the character at `index`, as one-character `TEXT`.
- **`repeat(text, times)`** is `text` written `times` times, one after another. `times` is truncated towards zero, and 0 or less gives `""`.

`length`, `split`, `trim`, `trimLeft` and `trimRight` take one required parameter, so a call can give it without its name, as `Text::trim(line)` does ([ADR 0020](0020-action-parameters.md)).

## Deferred

- **Grapheme clusters.** Counting and indexing what people see as characters, for text with accents or emoji made of several code points.
- **Searching and replacing.** Finding where a part of the text is, whether text starts or ends with another, and replacing parts of it.
- **Case.** Converting text to upper or lower case, which depends on language.
- **Very long results.** `repeat` can make text longer than the interpreter can hold, which panics for now.

## Consequences

- A program can take apart the text it reads: trim a line, split it into words, and read parts of it.
- Characters are code points, so an emoji counts as one character and a slice never cuts one in half, and the results are the same with every version of Unicode. Text with combining accents counts each accent as a character.
- `length` and `charAt` count code points, but ordering compares UTF-16 code units, so the two can disagree about text above `FFFF`.
- Indexes work as they do for arrays, so nothing in `cant::Text` raises an error, but a program checks `charAt`'s result for `NOTHING`.
- `cant::Text` and `cant::Collections` both export `length`, so a program that imports both with `import` places two `length`s in its namespace, which is a compile-time error ([ADR 0038](0038-namespaces-from-imports.md)). It imports one of them `into` a namespace of its own, as `import Collections into Collections`.
